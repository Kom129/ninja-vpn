# Рабочая спецификация и этапы

Это инженерное предложение, дополняющее подтверждённые пожелания. Полные основания находятся в research/REPORT.md.

## Границы компонентов

1. Интерфейс: режим, профиль, приложения, состояние, локальная диагностика.
2. Контроллер: модель данных, импорт, validation, выбор адаптера, резервирование.
3. Привилегированная служба: единое управление TUN, маршрутами, DNS, WFP и восстановлением.
4. Адаптеры сетевых ядер: запускают зафиксированные бинарники с проверенной конфигурацией, сообщают фактическое состояние.
5. Хранилище: настройки отдельно от секретов; версии схемы и миграции.
6. Обновление: аутентифицированные пакеты, совместимость, контролируемый откат.

## Сущности

| Сущность | Поля и смысл |
|---|---|
| Profile | id, имя, protocol, transport, security, endpoint, ссылка на секрет, требуемые capabilities |
| RoutePolicy | область whole-device/apps/browser, правила приложений, выбранный выход, direct-политика, unknown-process-политика |
| FallbackGroup | разрешённые profile id, приоритеты, ограничения страны/назначения, задержки и история отказов |
| EngineManifest | версия, хеш/подпись, платформа, зависимости, capabilities, версия схемы |
| Session | режим, активные выходы, этап соединения, проверка полезной передачи, защитная политика |
| DiagnosticEvent | время, компонент, стадия, код ошибки, без секретов и истории посещений по умолчанию |

Модель пользователя не должна быть копией всего сырого JSON одного ядра. Неизвестные поля импортированного файла сохраняются как данные либо отклоняются; они не исполняются и не удаляются молча при изменении смысла профиля.

## Состояния

`disconnected → preparing_protection → connecting → verifying → connected`

Отказы: `reconnecting`, `blocked_by_policy`, `failed`. Пользовательская остановка: `disconnecting → disconnected`, с явно определённой политикой сохранения/снятия защиты. Не смешивать доступность сети, состояние ядра и доступность полезной передачи. Зависший GUI не меняет сетевую политику службы.

## Приоритеты

| Этап | Реализовать | Условие перехода |
|---|---|---|
| P0 | Модель и validation, один движок, полный туннель, DNS/IPv6, события, WFP | Матрица аварий для защищённого трафика пройдена в тестовой Windows |
| P1 | Основные TCP/UDP-профили, адаптер XHTTP при необходимости, проверки передачи, резерв | Подтверждена совместимость конкретных клиентских/серверных сборок |
| P2 | Выбор приложений/браузера, helpers, DNS-политика, scoped kill switch | Захват пакетов подтверждает разделение маршрутов и отсутствие обхода защиты |
| P3 | Одновременные выходы, установка/обновления/откат, завершённый интерфейс | Релевантная матрица регрессий пройдена, пакет воспроизводим |
| Later | AWG, дополнительные корпоративные форматы, цепочки, экспериментальный DPI-модуль | Для каждой функции определены отдельные ограничения и проверки |

## Правила приёмки

- Неподдержанная capability обнаруживается до изменения сети.
- Direct существует только как явная политика; ошибки поиска процесса не ослабляют защиту.
- DNS, IPv6, WebRTC и UDP соответствуют обещанному охвату режима.
- Установка/удаление возвращают сетевую конфигурацию в согласованное состояние; чужие настройки не перезаписываются вслепую.
- Один TUN, несколько выходов; локальный Xray не перехватывает повторно собственные соединения.
- Отказ управляющего API не лишает доступа к сохранённым профилям и локальному интерфейсу.
- Анимация подписана на события и не имитирует факт подключения таймером.
- Для каждого релиза зафиксированы проверенные версии, выполненные тесты и известные ограничения.

Сроки, пропускная способность и потребление памяти не оценены измерениями. Не превращать их в обещания до прототипа.
