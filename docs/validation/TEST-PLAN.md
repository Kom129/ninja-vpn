# План проверки

Состояние: все сетевые проверки ещё не выполнены. Таблица test-cases.csv — исходный реестр, не отчёт об успешном тестировании.

## Стенд

Выделенная Windows VM/тестовая машина, контролируемые серверы совместимых версий, возможность захвата на физическом интерфейсе и имитации потерь/запретов. Фиксировать сборку ОС, ядро, конфигурацию без секретов, маршрут, время и сетевые условия. Не считать работу через loopback доказательством отсутствия утечек на физическом интерфейсе.

## Уровни

- Unit/schema: разбор профилей, несовместимые параметры, правила, миграции, исключение секретов из экспорта.
- Интеграция: протокол с настоящим совместимым сервером, локальный адаптер второго ядра, DNS и UDP.
- Система Windows: WFP/TUN/служба, существующие соединения, сон, смена сети, установка и восстановление.
- Продукт: область защиты, точный статус, выбор приложений, понятные ошибки, доступность UI.
- Полевые сети: несколько российских операторов/регионов и дат; выводы только в пределах фактической выборки.

## Доказательства

Для каждого прогона сохранить id проверки, дату, версии, условия, наблюдение, ожидаемый результат, статус PASS/FAIL/BLOCKED и ссылку на обезличенный артефакт. НЕ писать PASS, если проверен только mock. При отсутствии сервера или среды использовать BLOCKED с конкретной причиной.

Метрики: успешность подключения и передачи, время до полезного соединения, задержка/джиттер, длительность устойчивой сессии, скорость, число переподключений, CPU/RAM и служебный трафик. Никаких заранее придуманных процентов работоспособности. Сайт проверки IP дополняется анализом IPv4/IPv6/DNS/WebRTC и пакетного захвата.

## Выпуск

Сначала проходят критические проверки отсутствия непредусмотренного прямого выхода. Затем функциональность и совместимость. Провалы защиты блокируют соответствующий режим; UI не должен обещать его до исправления. После изменений ядра повторяются затронутые проверки, а полный набор — перед релизом по принятой политике регрессий.
