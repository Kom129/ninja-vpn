# Пакет для разработки VPN-клиента

Подготовлен 3 октября 2026 года для проекта **Россия → Windows**.

## Как использовать

1. Распаковать весь архив в рабочую папку проекта.
2. Открыть `01-DEVELOPMENT-PROMPT.md` и передать его текст помощнику по разработке вместе с этой папкой.
3. Для знакомства с выводами прочитать `research/REPORT.md`.
4. Посмотреть `design/selected-glass.png`; сверяться с `design/DESIGN-BRIEF.md` при работе над интерфейсом.
5. Реализацию начинать с технического прототипа по `spec/IMPLEMENTATION.md` и проверок `validation/TEST-PLAN.md`.

## Содержимое

| Файл | Назначение |
|---|---|
| `01-DEVELOPMENT-PROMPT.md` | Готовый основной промпт для следующей сессии разработки |
| `research/REPORT.md` | Подробное исследование, архитектура и ссылки на первичные источники |
| `research/sources.csv` | Машиночитаемый каталог источников из отчёта |
| `spec/PROJECT-CONTEXT.json` | Подтверждённые пожелания, рекомендации, неизвестные данные |
| `spec/IMPLEMENTATION.md` | Границы системы, сущности, порядок реализации и критерии готовности |
| `spec/profile-capabilities.json` | Предварительная карта совместимости; не готовый VPN-конфиг |
| `design/selected-glass.png` | Выбранный пользователем визуальный ориентир |
| `design/ninja-connection-reference.html` | Последняя уменьшенная и сглаженная демонстрация анимации |
| `design/DESIGN-BRIEF.md` | Визуальные предпочтения и требования к поведению |
| `validation/TEST-PLAN.md` | Что и как проверять перед выпуском |
| `validation/test-cases.csv` | Начальный реестр проверок, все со статусом NOT_RUN |
| `DECISIONS.md` | Принятые пожелания, предложенные решения и открытые вопросы |
| `MANIFEST.json` | Список файлов, размеры и SHA-256 для контроля целостности |

В пакете нет готового VPN-клиента, установщика, работающих серверных профилей, подписок или учётных данных. Исследование выполнено по документации; результаты сетевых испытаний отсутствуют. Визуальная демонстрация не подключает VPN. Статусы NOT_RUN намеренно сохранены.

Версии и сведения о блокировках — снимок на дату исследования. При реализации проверить первичные источники заново и зафиксировать реально испытанные версии. MANIFEST проверяет целостность содержимого, но не заменяет цифровую подпись выпуска приложения.
