# Пожелания, решения и открытые вопросы

## Подтверждено пользователем

- Основной регион — Россия, первая платформа — Windows.
- Поддержка VLESS и других VPN/прокси-протоколов.
- Режимы для всего устройства, одного/нескольких приложений и браузера.
- Несколько VPN-профилей; архитектура должна допускать их параллельное использование.
- Современный минимализм с возможностью расширения.
- Выбран светлый стеклянный дизайн с волной между браузером и сервером.
- Идея маленькой девушки-ниндзя с переносом файлов при подключении; при ошибке обрыв провода/нити.
- Первый персонаж оказался слишком большим, движение грубым; последняя версия уменьшена и сглажена. Отдельного финального утверждения до пикселя нет.
- Запрошены подробное исследование и архив с промптом/данными для дальнейшей работы.

## Рекомендовано исследованием, ещё не утверждено испытаниями

- Один владелец TUN/DNS/WFP; sing-box основной кандидат многопротокольного варианта.
- Адаптер Xray по необходимости, без второго системного TUN.
- Tauri 2 + React/TypeScript + Rust/Windows-служба.
- Независимая модель профилей, карта возможностей, валидируемый импорт.
- WFP fail-closed, независимые резервные серверы, диагностика полезной передачи.
- Этапы из spec/IMPLEMENTATION.md.

## Неизвестно; не выдумывать

- Название продукта, репозиторий, модель распространения и лицензия собственного кода.
- Собственные или сторонние серверы, их адреса, ключи и доступы.
- Минимальная версия Windows, необходимость x86/ARM64 и доступность тестовых VM.
- Бюджет серверов, число пользователей, требуется ли подписка/оплата.
- Политика DNS в режиме выбранных приложений и исключения LAN.
- Поведение при закрытии окна, перезапуске ОС и до входа пользователя.
- Допустимые группы резервирования, страны выхода и поведение явного отключения.

Эти вопросы задаются по мере появления зависимых задач. Они не мешают подготовить модель, адаптеры, UI-компоненты и лабораторные сценарии. Серверы и платёжный сервис не входят автоматически в разрешение на исследование.
